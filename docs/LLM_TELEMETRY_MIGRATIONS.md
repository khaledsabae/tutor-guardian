# First Phase 3 migration slice: llm_calls

This introduces an explicit numbered registry for **llm_calls only**. The gateway
still opens its existing `ops/sessions.db` path. `CONVERSATIONS_DB`, `init_db.py`,
the conversation store and its v35 stamp are unchanged. No stores are consolidated.
Migration code does not change `user_version`, foreign-key settings, journal mode
or busy timeout; gateway connection policy remains in its existing callers.

`app.db.migrations.runner.apply_migrations()` takes an open connection with no
caller-owned transaction. It acquires `BEGIN IMMEDIATE`, validates the namespaced
`schema_migrations` ledger, applies pending steps, validates the resulting schema,
records the checksum and commits. An error, SQLite interruption or cancellation
before commit rolls back DDL and ledger together. Two processes serialize on the
same database's writer lock. This is not a lock or transaction across both stores.
If a persistent cancellation callback or authorizer prevents rollback itself,
the runner closes the connection to roll back and release its lock, preserving
the original exception and never clearing the caller's policy. Discard that
failed connection; retry with a new one after resolving the cancellation cause.

The `llm_telemetry` registry currently contains `telemetry_0001_llm_calls.py`.
Its checksum is SHA-256 of that immutable source file. Once applied to any deployed
database, do not edit the file, including its comments: add a new numbered migration
instead. Entries must be numbered consecutively, and the existing ledger must be
an exact prefix with matching numbers, names and checksums. Unknown versions,
checksum/name drift and incompatible ledger keys are refused without repair.
Other ledger namespaces are preserved for independent future migrations.

Migration 1 creates the current table on an empty store or adopts the legacy core
table by adding only missing `tier TEXT` and `route_reason TEXT` columns. Existing
columns (including unrelated future budget extensions), indexes, IDs, sequence
counters, timestamps, NULLs and other values remain untouched. It validates the
core column affinities and the autogenerated INTEGER rowid key. Views, missing
core columns, incompatible types, generated core fields and non-rowid keys are
refused. A stamped database is revalidated: the old process-wide readiness flag
does not bypass another database, a replaced file or live schema drift.

Callbacks receive a small API for introspection and additive single-statement DDL,
without `commit`, `rollback` or `executescript`. Validation gets a read-only context.
These are trusted application callbacks, not a sandbox for untrusted Python. They
must use that API and never reach into the connection or a returned cursor's
connection. The historical v16/v20 standalone scripts commit on their own and
lower the old core stamp; they are **not** members of this registry and are not run.

Gateway logging, usage queries, budget-cache behavior and their existing error
policy are unchanged: telemetry errors do not break a reply; unreadable budget
telemetry reports `_BUDGET_UNKNOWN`. This slice does not change any pending budget
feature, provider selection, request accounting or network calls. Future budget
work can keep compatible llm_calls extensions or append an explicit migration.

Focused tests use synthetic temporary SQLite files only: empty/legacy/current
adoption, exact preservation, repeated no-op, caller transactions, injected ALTER
failure, cancellation/interruption, destructive SQL/script refusal, ledger/schema
drift, database replacement and two spawned startup workers. Existing gateway
logging and monthly-budget contracts are checked alongside them. No runtime or
user database is opened during development verification.

M17 remains pending beyond this slice: replacing the monolithic conversation
initializer, extracting the other seven sessions.db schema owners and remaining
lazy conversation DDL, and planning a backed-up, verified two-store cutover with
all service/retention/ops consumers and a tested rollback. Do not replay v16/v20
or perform that cutover as part of this change.
